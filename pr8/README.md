# Практична робота 8 

## Завдання 8.1

### Ідея реалізації

У програмі створюється `pipe`, записуючий дескриптор переводиться у `O_NONBLOCK`, канал заповнюється майже повністю, після чого виконується великий `write()`.
За таких умов (особливо коли `nbytes > PIPE_BUF`) `write()` може виконати **частковий запис** і повернути `count < nbytes`.

### Запуск

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task1.c -o task1
./task1
```

### Технічні особливості

- Використано системні виклики: `pipe`, `fcntl`, `read`, `write`.
- Показано практичний випадок partial write для неблокуючого дескриптора.
- На Linux розмір pipe може відрізнятися між системами.

## Завдання 8.2

### Ідея реалізації

Програма створює файл із байтами:
`4, 5, 2, 2, 3, 3, 7, 9, 1, 5`.
Після `lseek(fd, 3, SEEK_SET)` виконується `read(..., 4)`.

Через нульову індексацію offset `3` означає 4-й байт у файлі, тож читаються байти з позицій `3..6`.

### Запуск

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task2.c -o task2
./task2
```

### Технічні особливості

- Використано `open`, `write`, `lseek`, `read`.
- Файл для демонстрації: `task8_2_data.bin`.
- Приклад відтворюваний і не залежить від зовнішніх даних.

## Завдання 8.3

### Ідея реалізації

Реалізовано програму-дослідження для `qsort`:

1. Вимірювання кількості викликів функції порівняння та часу сортування.
2. Тестування наборів шаблонних вхідних даних:
   `ascending`, `descending`, `all_equal`, `random`, `organ_pipe`, `sawtooth`, `alternating_ends`, `nearly_sorted`.
3. Автоматичний підбір «повільного» набору даних (`auto_searched`) через мутації масиву і відбір кандидатів з більшою кількістю порівнянь.
4. Набір тестів коректності для `qsort`:
   - крайні випадки (порожній масив, 1 елемент),
   - відсортований / обернений,
   - дублікати,
   - змішані значення,
   - fuzz-тести випадкових масивів.

Для перевірки правильності результат `qsort` порівнюється з еталонним сортуванням (власна реалізація merge sort).

### Запуск

Режим експерименту:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task3.c -o task3
./task3 --experiment
```

З параметрами:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task3.c -o task3
./task3 --experiment 20000 5 300
```

де:
- `20000` — розмір масиву `n`,
- `5` — кількість повторів вимірювання,
- `300` — ітерації автопошуку «повільного» набору.

Режим тільки тестів:

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task3.c -o task3
./task3 --tests
```

### Технічні особливості

- Важливо: `qsort` — стандартизований інтерфейс, але внутрішній алгоритм залежить від реалізації libc.
- Тому програма робить **емпіричний** аналіз саме для вашої системи.
- Функція порівняння написана без віднімання (`x - y`), щоб уникнути переповнення `int`.

## Завдання 8.4

### Ідея реалізації

Програма з `fork()` завершена так, щоб:

- обробляти помилку `fork()`,
- друкувати значення, яке повернув `fork()` у кожному процесі,
- батьківський процес чекав на дочірній через `waitpid()`.

### Запуск

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task4.c -o task4
./task4
```

### Технічні особливості

- При успішному `fork()`:
  - у дочірньому процесі `pid == 0`,
  - у батьківському `pid == PID_дочірнього`.
- Порядок рядків у виводі може змінюватись через планування процесів ядром.

## Завдання 8.5

### Ідея реалізації

Програма демонструє різницю:

- `dup(fd)` повертає **найменший вільний** дескриптор.
- `dup2(fd, target_fd)` дублює дескриптор **точно в `target_fd`** (закриваючи `target_fd`, якщо був відкритий).

У прикладі обидва варіанти перенаправляють `stdout` у різні файли:
- `dup_output.txt`
- `dup2_output.txt`

### Запуск

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 task5.c -o task5
./task5
```

### Технічні особливості

- Діагностичні повідомлення виводяться у `stderr`, щоб залишатись видимими під час перенаправлення `stdout`.
- Після кожної демонстрації `stdout` відновлюється з резервної копії дескриптора.
