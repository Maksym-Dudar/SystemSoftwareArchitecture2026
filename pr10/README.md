# Практична робота 10

## 1) `crash_diag.c`
**Про що програма:**
Демонстраційна утиліта для перехоплення аварійного завершення процесу (наприклад, `SIGSEGV`) та виведення діагностичної інформації про збій.

**Технічні особливості:**
- Встановлює обробники сигналів `SIGSEGV`, `SIGBUS`, `SIGFPE`, `SIGILL`, `SIGABRT` через `sigaction` з прапором `SA_SIGINFO`.
- У хендлері використовує low-level `write()` (а не `printf`), що безпечніше в контексті сигналу.
- Виводить `signal`, `si_code`, адресу помилки (`si_addr`) та дамп регістрів з `ucontext_t`.
- Має архітектурно-залежний вивід регістрів для `__x86_64__` і `__aarch64__`.
- Завершує процес через `_exit(128 + sig)` після обробки збою.

**Компіляція:**
```bash
gcc -std=c11 -Wall -Wextra -pedantic crash_diag.c -o crash_diag
```

**Запуск:**
```bash
./crash_diag
```

## 2) `rt_pubsub.c`
**Про що програма:**
Невелика модель publisher/subscriber на POSIX real-time сигналах: один процес надсилає цілочисельні повідомлення, інший їх приймає.

**Технічні особливості:**
- Канал обміну побудований на `SIGRTMIN` + `sigqueue()` з передачею payload через `sigval.sival_int`.
- Режими роботи:
- `sub` — безкінечне очікування через `sigwaitinfo()`.
- `sub-timeout` — очікування з таймаутом через `sigtimedwait()` (5 секунд).
- Перед очікуванням сигнал блокується через `sigprocmask(SIG_BLOCK, ...)`, щоб уникнути некерованої доставки.
- Валідує аргументи командного рядка (`strtol`) та виводить метадані відправника (`si_pid`, `si_uid`).
- Негативне значення повідомлення використовується як сигнал завершення subscriber.

**Компіляція:**
```bash
gcc -std=c11 -Wall -Wextra -pedantic rt_pubsub.c -o rt_pubsub
```

**Запуск:**
```bash
./rt_pubsub.c
```

## 3) `sleep_correct.c`
**Про що програма:**
Порівнює два підходи до сну процесу при перериваннях сигналом: відносний `nanosleep` та абсолютний `clock_nanosleep` для періодичних тікiв.

**Технічні особливості:**
- Встановлює обробник `SIGUSR1`, який виставляє прапорець `sig_atomic_t`.
- Для відносного сну реалізований restart-loop: при `EINTR` залишок часу береться з `rem` і сон продовжується.
- Для періодичної роботи використовується `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, ...)`.
- Абсолютний дедлайн зменшує накопичення drift у порівнянні з повторними relative sleep.
- Періодичні “tick” виконуються з кроком 1 секунда, базуючись на монотонному годиннику.

**Компіляція:**
```bash
gcc -std=c11 -Wall -Wextra -pedantic sleep_correct.c -o sleep_correct
```

**Запуск:**
```bash
./sleep_correct
```

## 4) `task7.c`
**Про що завдання:**
Реалізувати сигналобезпечну обробку помилки, яка намагається коректно завершити програму та звільнити всі критичні ресурси: сокети, тимчасовий файл і буферизовані потоки.

**Технічні особливості:**
- Використано async-signal-safe обробник сигналів (`SIGINT`, `SIGTERM`, `SIGUSR1`) на базі `sigaction`.
- У хендлері виконуються тільки безпечні дії для контексту сигналу: `write`, `close`, `unlink`, оновлення `sig_atomic_t` прапорців.
- Ресурси моделюються явно: `socketpair(...)` для сокетів, `mkstemp(...)` для тимчасового файлу, `fdopen(...)`/`setvbuf(...)` для буферизованого потокового запису.
- Використано двофазне завершення:
- аварійне (мінімальне, сигналобезпечне) прибирання прямо в хендлері;
- повне завершення в основному потоці з `fflush(NULL)` та `fclose(...)`.
- Програма працює циклічно, поки не отримає сигнал завершення.

**Компіляція:**
```bash
gcc -std=c11 -Wall -Wextra -pedantic task7.c -o task7
```

**Запуск:**
```bash
./task7
```
