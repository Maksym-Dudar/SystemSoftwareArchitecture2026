# Практична робота 9 

## Вимоги

- Linux-система з `bash`
- базові утиліти: `getent`, `id`, `whoami`, `ls`, `awk`, `sed`
- для завдань з підвищенням привілеїв: `sudo` (або `pkexec`, де вказано)
- Скрипти з `sudo` можуть запитувати пароль адміністратора.


## Звіт по завданнях

### Завдання 9.1

**Реалізація:**  
`task1.sh` читає облікові записи через `getent passwd`, визначає поріг UID регулярних користувачів через `UID_MIN` (з `/etc/login.defs`, fallback `1000`) і перевіряє, чи існують інші звичайні користувачі, окрім поточного.

**Технічні особливості:**  
- не читає `/etc/passwd` напряму, а використовує NSS-шар (`getent`);
- поріг UID адаптується до дистрибутива.
  
**Запуск скрипта**  
```bash
chmod +x task*.sh
./task1.sh
```

### Завдання 9.3

**Реалізація:**  
`task3.sh`:
1. створює файл від імені звичайного користувача;
2. копіює його від імені root в домашній каталог користувача;
3. змінює власника копії на `root:root` і права на `0644`;
4. пробує від звичайного користувача змінити файл;
5. пробує видалити файл командою `rm`.

**Технічні особливості:**  
- демонстрація різниці між правами на файл і правами на каталог;
- показує типову поведінку: запис у root-owned файл заборонено, а видалення залежить від прав каталогу.
  
**Запуск скрипта**  
```bash
chmod +x task*.sh
./task3.sh
```

### Завдання 9.5

**Реалізація:**  
`task5.sh` створює файл від імені звичайного користувача, далі від імені root змінює `chown`/`chmod` для кількох сценаріїв і перевіряє, чи може поточний користувач читати/писати файл.

**Технічні особливості:**  
- матриця сценаріїв доступу (`root:root 600`, `root:root 644`, `root:root 666`, `user:user 600`);
- автоматична перевірка read/write після кожної зміни прав.
  
**Запуск скрипта**

### Завдання 9.6

**Реалізація:**  
`task6.sh` виконує `ls -l` для домашнього каталогу, `/usr/bin` і `/etc`, а потім робить спроби `read/write/execute` для файлів з різними правами та власниками.

**Технічні особливості:**  
- порівняння доступу до user-owned файлу, `/usr/bin/ls`, `/etc/passwd`, `/etc/shadow`;
- окремий блок демонструє "обхід" прав через адмін-доступ (читання `/etc/shadow` за допомогою `sudo`).
  
**Запуск скрипта**

### Завдання 9.7

**Реалізація:**  
`task7.sh` моделює некоректні/неповні дані `getent passwd` через mock-файл і валідує записи (кількість полів, числовий UID/GID, валідність home, shell).

**Технічні особливості:**  
- не ламає системні джерела облікових записів, а працює на змодельованому наборі;
- пояснює практичні причини, чому `getent passwd` може повертати погані дані (NSS/LDAP/SSSD/кеш/timeout/пошкоджені записи).
  
**Запуск скрипта**  
```bash
chmod +x task*.sh
./task7.sh
```
